[画面・採用判断](UI_UX_REVIEW.md#parent-notification-implementation-20261016)。以下は本人の公開指示で本番へ反映したv2の実装。旧調査・旧システムの一覧は後段に保持する。

|---|---|

既存13種類＋請求取消し1種類。通常の完了メールを一律に追加しない。保護者メールにはLINE／指定メールの連絡先を添え、返信先を mugilives@gmail.com にする。旧版の招待・再設定や対象のない旧URLは互換を維持する。

### 送信記録と再案内

- Workerは通知ごとの送信IDを発行し、代行側はそのIDに対して結果を返す。代行処理の途中で応答が切れた場合は「結果不明」とし、成功や未送信と推測しない。
- 代行は送信前にIDを記録する。同じIDの再要求には記録済みの結果を返し、送信途中・不明なものを再送しない。送信済みの控えは30日後に整理し、不明な控えは自動削除しない。送信済みを一括再送する機能は追加しない。
- 未送信と確認できる失敗だけを上限3回で再試行する。再試行前に対象の状態・版・宛先・有効期限を確認し、承認済み／変更／取消し／失効した依頼を新しい依頼として送らない。
- 結果不明は管理者が受信状況と根拠を確認して記録する。日程通知は通常の再送と分け、予定画面で再案内・回答期間を確認する。送信成功は既読を意味しない。
- 旧代行応答で個別の成否を確定できなければ不明として残す。従来の「送信中」のまま止まった記録も自動再送しない。
- 新しい通知記録がない既存の確認待ち予定も、自動確定の根拠を推測しない。公開前に教室側で対象を確認し、必要に応じて再案内する。既存の明示的な合意・予約は書き換えない。

## 通知文面とリンクを整える作業案（2026-10-16・実装前の記録）

作業順と公開条件は [改善手順案](UI_UX_REVIEW.md#parent-notification-plan-20261016)。現在の13種類について、本文だけでなく開く画面・操作・完了表示を一組で作る。以下は文面作成の要件であり、送信中の本文ではない。

| 通知のまとまり | 件名・本文で最初に伝える用事 | 開いた先と次の行動 | 整合確認 |
|---|---|---|---|
| 登録・再設定 | 保護者ページの登録／パスワード再設定 | 設定画面。無効な場合はログイン・再案内依頼・再設定の入口 | 7日／30分の現行期限、古いリンクの失効、元の用事への復帰 |
| 通常条件・特殊条件 | 何の条件と料金への同意をお願いしているか | 対象条件の全文・説明 → 同意／承認 | 表示名称と適用する書面の版、対象生徒・期間・単価 |
| 合意書の初回・再案内 | 対象月の科目・回数・時間・料金の確認 | 対象の受講合意書 → 承認／変更希望の連絡 → 控え・PDF保存 | 予定総額と請求額の区別、先行同意が必要な理由、承認前の案と承認後の控え |
| 日程の確認依頼 | 授業日時を確かめてほしいこと | 対象生徒の確認待ち一覧 → 日時の確認／都合の悪い授業の連絡 | 期限別の説明、近い授業は返事が必要、現在の一覧を開くこと、金額・回数の承認と別であること |
| 日時確定・変更・授業取消し | 決まったこと／変更前後／取り消した授業 | 対象の授業と現在の状態 | 生徒・科目・日時、返事の要否、該当するキャンセル料金の扱い |
| キャンセル料金・申請回答 | どの授業の料金／どの申請への回答か | 対象の料金・根拠・回答 → 必要なら問い合わせ | 対象日時・金額、回答待ち・請求済み等の状態、いつ支払うものか |
| 月ごとの請求 | 対象月の確定額と支払期限 | 請求詳細・振込先 → 振込 → 振込の連絡 | メール・画面・請求書の期日、合意済みの支払条件、取消済み請求の表示 |

- 共通の並びは「対象 → してほしいこと／お知らせのみ → 期限と無回答時の扱い → 目的のリンク → 困ったときの連絡先」。
- 件名は用事・対象月を優先し、生徒名は本文で示す案。口座情報はログイン後に確認する案。新たな期限・同意条件は作らない。
- LINEやメールの連絡先は既定の案内とそろえる。「このメールに返信」と書く場合は、実際の返信先と受け付ける運用を先に確認する。
- 通常の業務リンクに認証用の鍵を入れない。登録・再設定の鍵をログや共有資料に残さない。
- 規約の案内・請求取消し等の新規通知と、日程依頼ごとの専用ページは手順案の判断D2・D4。未判断のものを現行13種類の修正に紛れ込ませない。
- 完成確認は13種類ごとに行い、初回と再案内で必要情報が欠けたり、メールと画面で別の操作名になったりしないことを確認する。

### 現在の送信・受信の扱い

- 業務通知は、生徒に紐づく家族の登録メール1件に送り、家族が active でない・アドレスがないと通知を作らず戻る。宛先不在の理由を通知側の戻り値では示さない。[familyNotice](https://github.com/mugilives-max/stepwise-kobetsu/blob/d13c5e0ce8b7f34a41b8a8e446d4aab096e36a36/cf/v2/schedule.mjs#L99-L103)
- 差出人名は「ステップワイズ個別指導」。本文末尾は保護者ページのURL。共通の問い合わせ案内・返信先の説明はない。メール代行側は `name` を渡すが `replyTo` は指定しない。実際の From / Reply-To ヘッダーは今回未確認。[代行](https://github.com/mugilives-max/stepwise-kobetsu/blob/d13c5e0ce8b7f34a41b8a8e446d4aab096e36a36/gas-effects/Code.gs#L48-L54)
- 控えは v2 の `effects` 表。テスト用・切替前の保護者通知は dismissed として送信しない。失敗等の再試行は48時間以内・試行回数3未満、停止中の pending の回収もある。旧節の「自動では送り直さない」「通知種類を本人が停止できる」を v2 の仕様として使わない。[記録・送信](https://github.com/mugilives-max/stepwise-kobetsu/blob/d13c5e0ce8b7f34a41b8a8e446d4aab096e36a36/cf/v2/effects.mjs#L1-L39)、[再試行](https://github.com/mugilives-max/stepwise-kobetsu/blob/d13c5e0ce8b7f34a41b8a8e446d4aab096e36a36/cf/v2/effects-admin.mjs#L60-L87)
- **個別のメール失敗を sent と記録する再現あり**（調査 PN-03）。「送信済み」の記録だけでは、送信処理の成功・受信箱への到達を保証できない。実メールの未着事例は今回調べていない。
- 日程の案内は依頼ごとのURLではなく、家庭の現在の確認待ち一覧を開く。既存の設計判断を踏襲する場合も、対象生徒・対象授業・回答期限を画面上で識別できる必要がある。
- 登録・再設定メールを出し直すと、同じ用途の古いリンクは無効になる。期限切れ・使用済みのエラーはあるが、登録エラー画面に問い合わせ・ログインへのリンクがない。[accounts](https://github.com/mugilives-max/stepwise-kobetsu/blob/d13c5e0ce8b7f34a41b8a8e446d4aab096e36a36/cf/v2/accounts.mjs#L87-L105)、[family](https://github.com/mugilives-max/stepwise-kobetsu/blob/d13c5e0ce8b7f34a41b8a8e446d4aab096e36a36/family/app.js#L54-L58)

### メールがない操作（追加の要否は未決）

規約の版の設定、LINE等の承諾を管理者が記録、保護者の承認・日程確定への保護者宛て完了通知、請求取消し、入金確認、授業記録公開・宿題更新には、この調査対象の v2 経路で保護者宛てメール生成を確認していない。画面上の状態更新や、管理者宛て通知とは分ける。

特に旧システムと違い、**v2の自動請求確定は通知を作る一方、請求取消しは保護者メールを作らない**。何でもメールを増やす方針は採らず、「金額・約束が変わる重要連絡」「操作完了」「日常の学習記録」を分けて要否を決める。

## 旧システムの記録（2026-10-01時点）

以下の共通事項・各一覧・見直し候補は旧システムの調査記録。v2 の送信仕様と混同しないこと。

## 共通のしくみ

- **送るのは Apps Script**。台帳の正本は Worker（D1）で、Worker はメールを「付随処理」として控え（`_effects`）に記録し、応答を返したあとで Apps Script に送信を頼む。送った記録は管理画面の「設定 → 送信の記録」（`#sendlog`）で見られる。失敗したものは「送れなかった処理」に残り、自動では送り直さない。
- **差出人**は先生の Google アカウント（Apps Script の所有者）。生徒・保護者あての差出人名は「ステップワイズ英数教室」。
- **テストの生徒・家族には実際には送らない**。名前が【テスト】の生徒、テスト用の家族は「送ったことにする」だけ（記録の状態は `suppressed`）。
- **生徒・保護者あての業務メールは、受信確認済みのアドレスにだけ送る**。未確認なら送らずに `skipped` として記録する。
- **本人が種類ごとに止められる**。生徒はマイページの「設定 → メールで受け取る項目」、保護者は保護者ページの「設定 → メール通知」。止めた種類は `skipped`（本人の通知設定でオフ）として記録する。認証・登録のメールは止められない。
- **二重送信を防ぐ**。同じ出来事には同じ通知 ID を付け、同じ ID のメールは二度送らない。送信結果が分からなくなったものは `uncertain` にして自動では再送しない。
- **1日の送信上限**（Apps Script の上限）に達したら送らず `failed` にする。
- 記録の場所: 生徒あて `studentEmailOutbox`、保護者あて `familyOutbox`（どちらも台帳）、送信そのもの `_effects`（Worker）。

先生の Google アカウントに届く。件名の頭は「[ステップワイズ予約]」。管理画面の「設定 → 先生に届くメール」で、全体（台帳の `emailNotify`）と種類ごと（`teacherMail.<種類>`）にオン・オフできる（2026-10-01 から）。種類は件名の頭で見分ける（`gas/Code.gs` の `TEACHER_MAIL_KINDS_`）。テストの生徒の出来事では送らない。

| 件名 | 送るとき |
|---|---|
| 【確定】（生徒名）さん N件 | 生徒が締め切りのない案内を自分で決定したとき。先生の直接決定・締め切りでの自動決定では送らない |
| 【お休みの連絡】（生徒名）さん | 生徒・保護者が前日23時までに「お休みにする」を選んだとき（決定した授業・仮予定とも。2026-10-01 から。旧【取消依頼】【日時が合わない】） |
| 【キャンセル】（生徒名）さん | 前日23時を過ぎてから「キャンセルする」を選んだとき（キャンセル料の対象）。同じ連絡の再送では送らない |
| 【日時の変更のお願い】（生徒名）さん | 生徒・保護者が「日時の変更をお願いする」を選んだとき。希望の一言を書く（2026-10-01 から） |
| 【開始を遅らせたい】（生徒名）さん | 前日23時から開始までに「開始を遅らせたい」を選んだとき（2026-10-01 から） |
| 【お願いの取り下げ】（生徒名）さん | お休み・キャンセル・日時の変更のお願いを本人が取り下げたとき（旧【取消依頼の取り下げ】） |
| 【共有予定】（生徒名）さん | 生徒がマイページで予定（テスト・行事など）を共有したとき（先生が登録した予定では送らない） |

| 【授業計画の回答】（生徒名）さん … | 保護者が授業計画を承認・回数調整・見送りしたとき |

## メールでは送らないもの

- **返事前の案内の取り下げ**: 生徒へのメールは送らない。生徒のページから案内が消えるだけ（2026-10-01 から）。
- **授業記録の公開・宿題の反映**: メールは送らない。生徒・保護者のページに出る。
- **毎月3日の請求の自動確定**: メールは送らない。保護者ページの「請求・お支払い」に出る。
- **保護者からの振込の連絡**: 先生へのメールはない。管理画面の請求ページに「入金の確認待ち」として出る。
- **連絡欄（生徒・保護者からのメッセージ）**: メールは送らない。

## メール以外の通知（アプリの通知）

ホーム画面に追加したアプリで通知を許可した端末にだけ届く（Web プッシュ、`cf/worker/push.mjs`）。メールとは別に、次の2つだけ。

| 相手 | 表題 | 送るとき |
|---|---|---|
| 生徒 | 授業の案内が届きました | 先生が「今すぐ送る」で仮予定を送ったとき（「あとで送る」では送らない） |
| 生徒 | 授業予定表が届きました | 先生が「予定表を送る」を押したとき（2026-10-01 から） |
| 保護者 | 学習計画の承認のお願い | 先生が授業計画を保護者に送ったとき |

## 見直し候補（2026-10-01 に洗い出したもの）

不要なメールや分かりにくいメールになっていそうな所。直すかどうかは先生が決める。

1. ~~返事前の案内を取り下げても「授業を取り消しました」が届く~~ → **対応済み（2026-10-01）**: 取り下げではメールを送らない。
2. ~~先生が生徒の承認を待たずに登録した授業で、生徒に確定のメールが届かず、先生自身に【確定】メールが届く~~ → **対応済み（2026-10-01）**: 生徒に「授業を登録しました（返事は不要です）」を送り、先生への【確定】は送らない。
3. ~~保護者あての請求メールの文面が「月謝」のまま~~ → **対応済み（2026-10-01）**: 「授業料の請求」に直した。
4. **請求のメールが、手で記録したときだけ届き、毎月3日の自動確定では届かない**。保護者から見ると月によって届いたり届かなかったりする。どちらかに揃える。
5. ~~生徒の取消依頼が新しく出されても先生にメールが来ない~~ → **対応済み（2026-10-01）**: 【取消依頼】を先生に送る。
6. ~~先生あての通知は種類ごとに止められない~~ → **対応済み（2026-10-01）**: 設定ページで種類ごとにオン・オフできる。
7. ~~科目の書き間違いを直しただけでも「授業の予定を変更しました」が届く~~ → **対応済み（2026-10-01）**: 日時・時間・形式が変わらない修正では送らない。日時と一緒に科目も変えたときは、新しい科目でメールに載る。
